# 복지 기사 검토 AI의 데이터 선정과 평가 기준

2026 TRAITHON에서 아쿠아넷(AquaNet) 팀의 데이터과학자로 참여했다. 

복지 기사 검토 AI에 사용할 데이터를 선정하고, 조건별 기준 답안을 작성했으며, 엔지니어와 평가 요구사항을 조율했다.

## 대회에서 요구한 과제

TRAITHON은 AI 신뢰성을 주제로, AI가 사용자와 사회에 미칠 영향과 위험을 분석하고 필요한 신뢰성 활동을 설계·수행하는 경진대회다.

2026년 과제는 AI Hub 등의 데이터와 SK A.X 모델을 활용해 클릭베이트 탐지 AI를 구현하고, AI가 판단·조치할 범위와 사람에게 판단을 넘겨야 할 조건을 함께 설계하는 것이었다. 수행 과정과 결과를 근거로 남기는 것도 중요한 요구사항이었다.

- 예선: 서비스와 사용자를 정의하고, 영향·위험을 분석해 신뢰성 활동과 프로토타입 계획
- 본선: 계획을 실제 구현과 시험으로 확인하고, 관찰한 결과를 바탕으로 설계를 보완
- 수행 근거: 무엇을 시도했고, 무엇을 확인했으며, 어떤 판단으로 변경했는지 기록

## 우리 팀이 기획한 서비스

아쿠아넷은 복지 기사 제목의 지원 조건을 본문 근거와 대조하고, 기사 검수자의 후속 판단을 돕는 AI 서비스를 기획했다.

생활안정지원금·생계급여 관련 기사에서는 ‘최대 지급액’을 정액처럼 표현하거나 신청 기간과 지급 기간을 혼동하면 독자가 지원 조건을 잘못 이해할 수 있다. 팀은 정보 신뢰성이라는 넓은 문제에서 출발해, 제목과 본문 사이의 조건 비교로 과업을 좁혔다.

검수자가 확인할 내용을 대상·금액·지역·기간·확정성의 다섯 조건으로 나누고, 원문 근거와 함께 후속 검토로 연결하는 것을 목표로 했다. 검토 범위는 제목과 대응 본문의 관계이며, 정책의 사실 여부나 개인의 수급 자격을 인증하는 기능은 포함하지 않았다.

## 기획에서 중요하게 본 것

팀은 잘못된 기사가 통과되는 문제와 함께, 정상 정보가 지나치게 보류되어 전달이 늦어지는 문제와 검수자의 업무 부담을 고려했다.

예선에서는 조건부 자동 통과·사전 사람 검토·보류의 세 경로와 검토 순서를 구상했다. 본선에서는 데이터와 모델의 제약을 확인하며 구현 범위를 조정했다.

현재 구현은 실제 게시 없이 ‘자동 게재’와 ‘사람 검토’ 두 경로를 기록하는 방식이다. 값 비교는 금액·기간·지역을 중심으로 하며, 대상·확정성의 의미 비교, 보류 경로와 검토 우선순위는 현재 구현 범위에 포함하지 않았다.

## 수행 과정: TRY → OBSERVE → DECIDE → CHANGE

아래는 개인의 데이터 작업과 협업 과정을 시도·관찰·판단·변경의 흐름으로 정리한 것이다.

### 1. 검색된 기사에서 서비스에 필요한 자료를 선정했다

**TRY · 키워드로 후보를 탐색했다**

‘지원금·급여·생계’를 제목과 본문에서 각각 검색했다. 규칙·AI 기반 사전 분류를 보조적으로 활용하고, 후보·보류 및 경계 사례의 원문을 검토했다.

**OBSERVE · 검색 일치와 서비스 적합성이 달랐다**

검색 결과에는 임금이나 기업 지원처럼 서비스 범위와 다른 자료도 포함됐다. 같은 기사가 여러 키워드 또는 제목·본문 검색에 반복해서 나타났으며, 실제 사용할 수 있는 후보는 검색 결과에 비해 적었다.

**DECIDE · 포함 범위와 중복 단위를 구분했다**

단어의 포함 여부에 더해 지원 제도의 성격과 기사 맥락을 살폈다. 중복은 기사 ID, 본문, 제목·본문 쌍으로 나눠 확인했다. 본문이 같더라도 제목이 다르면 별도의 비교 사례가 될 수 있다고 보았다.

**CHANGE · 검색을 보완하고 최종 자료를 정리했다**

관련 제도명으로 추가 탐색하고, 본문 담당 후보와 제목 담당 후보의 중복을 대조했다. 사용가능후보 44건과 경계시험용 13건, 총 57건의 기사 묶음을 구성하는 데 참여했다.

### 2. 조건별 판정과 근거를 비교할 수 있게 정리했다

**TRY · 다섯 조건의 기준 답안을 작성했다**

기사 44건에 대해 대상·금액·지역·기간·확정성의 총 220개 판정과 근거를 작성했다. 다른 작업자도 같은 자료를 별도로 판정했다.

**OBSERVE · 같은 표현도 비교 맥락에 따라 판단이 달라졌다**

총사업비의 반올림과 개인 지급액의 상한 생략은 서로 다른 문제였다. 신청 기간과 사용기한, 정책 권고와 시행 확정도 구분해야 했다. 제목이 해당 조건을 말하지 않은 경우와 본문에 대응 근거가 없는 경우 역시 달랐다.

**DECIDE · 같은 사업·대상·단위·시점을 비교하도록 기준을 구체화했다**

숫자나 단어가 같은지만 보지 않고 무엇을 비교하는지 먼저 확인했다. 판정은 ‘일치·차이·근거 없음·제목 주장 없음’으로 구분하고, 제목 표현과 본문 근거, 판단 이유를 함께 기록했다.

**CHANGE · 작업자 간 차이를 조정하고 기준 답안을 통합했다**

기사 ID와 조건을 기준으로 두 작업자의 결과를 대응시켰다. 판정이 다른 항목은 근거를 다시 확인하며 기준을 조정했고, 원안과 통합 결과를 구분해 정리했다.

### 3. 사람 라벨과 모델 출력의 비교 단위를 조율했다

**TRY · 조건별 평가를 위한 출력 연결을 요청했다**

엔지니어에게 모델 결과를 사람 기준 답안과 비교할 수 있도록 조건별 결과를 요청했다.

**OBSERVE · JSON 출력만으로는 필요한 비교가 되지 않았다**

기존 출력에는 기사 전체의 판정·인용·이유가 있었지만, 다섯 조건 각각의 기준 답안에 대응하는 결과는 없었다. 또한 이후 구현에서는 사람이 판단한 ‘의미 일치’와 시스템의 ‘근거 문장 선택’이 서로 다른 내용을 나타낼 수 있었다.

**DECIDE · 출력 형식과 평가 의미를 함께 정의했다**

기사 ID와 조건을 연결 기준으로 삼고, 판정값·제목 인용·본문 근거·위치·이유가 필요한 이유를 설명했다. 서비스 범위 판단, 조건별 비교, 후속 처리 경로도 구분하도록 요구사항을 정리했다.

**CHANGE · 평가 요구사항과 결과 해석 기준을 명확히 했다**

사람 라벨이 모델 결과와 대조할 기준 답안이라는 목적을 전달했다. 팀의 구현 변경 이후에는 근거 문장을 선택했다는 사실을 의미상 올바르게 판단했다는 결과와 구분해 해석했다.

### 4. 사람 검토 조건에 대한 제안을 구체화했다

**TRY · 제한 조건 생략을 사람 검토 대상으로 제안했다**

본문의 ‘최대’ 금액 제한이 제목에서 생략된 사례에서, 숫자가 같아도 의미가 달라질 수 있다는 의견을 냈다. 이러한 사례를 사람이 확인하는 방식을 제안했다.

**OBSERVE · 일괄적인 검토 요청은 업무량을 늘릴 수 있었다**

‘최대’라는 표현의 유무만으로 모든 기사를 넘기면 검수 부담이 커질 수 있다고 보았다. 오류를 놓쳤을 때의 영향과 사람이 처리할 수 있는 양을 함께 고려할 필요가 있었다.

**DECIDE · 위험 신호와 검토 우선순위를 구분했다**

제한 조건 생략을 위험 신호로 보되, 수령액 오해나 신청 기회 상실 등 예상 영향이 큰 사례를 사람이 우선 확인하는 방향을 생각했다.

**CHANGE · 제안에 영향과 검토 지원 방식을 추가했다**

검수자가 확인할 구절과 위치를 안내하고, 모델이 일치로 판단해도 별도의 위험 기준에 해당하면 사람이 확인하는 방식을 제안했다.

이 항목의 변경은 개인 제안의 구체화다. 우선순위 기능을 구현하거나 검토 시간 감소를 측정한 성과는 아니다.

## 현재까지의 결과

| 결과 | 범위 |
| --- | --- |
| 최종 기사 묶음 구성 참여 | 사용가능후보 44건 + 경계시험용 13건 = 57건 |
| 개인 라벨링 | 44건 × 5조건 = 220개 판정과 근거 |
| 공동 기준 조정 | 두 작업자의 판정 차이를 비교하고 기준 답안 통합 |
| 엔지니어 협업 | 조건별 비교 단위, 기준 답안의 목적, 출력 연결 요구사항 정리 |
| 운영 관점 제안 | 오류의 영향과 검수 부담을 고려한 인간 검토 조건 논의 |

모델 구현과 오프라인 실험은 팀의 모델링 담당자가 수행했다. 최종 57건은 반복 개발에 사용한 자료이며, 새로운 기사에 대한 독립 평가 성능과 실제 서비스 효과는 아직 확인하지 않았다.

## 배운 점

데이터의 양뿐 아니라 서비스 목적에 맞는 자료인지, 서로 같은 단위를 비교하고 있는지, 결과가 실제로 어떤 판단을 뒷받침하는지가 중요했다.

특히 AI의 결과를 평가하는 기준과 사람에게 검토를 요청하는 운영 기준을 구분하게 됐다. 조건의 차이를 찾는 일에 더해, 그 차이가 어떤 영향을 만들고 사람이 무엇을 확인해야 하는지까지 고려하는 경험이었다.
