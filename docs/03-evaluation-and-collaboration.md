# 평가 기준과 협업

[프로젝트 소개](../README.md)

## 1. 서비스 질문에 맞는 기준 답안을 작성했다

제공 데이터의 낚시성 라벨만으로는 제목의 금액·기간·정책 단계가 본문과 어떻게 다른지 평가하기 어려웠다.

나는 데이터팀 작업자로서 기사 44건의 대상·금액·지역·기간·확정성을 판정하고 근거를 기록했다.

| 항목 | 작업 단위 |
| --- | --- |
| 개인 판정 | 44건 × 5조건 = 220개 |
| 다른 작업자의 판정 | 같은 44건의 220개 조건을 별도로 작성 |
| 두 작업자의 입력 | 총 440개 판정 |
| 통합 기준 답안 | 고유한 220개 조건 |

두 사람이 작성한 440개 판정을 서로 다른 평가 조건 440개로 세지 않았다. 사람 라벨의 목적은 모델 결과와 대조할 기준을 마련하는 것이었다.

## 2. 네 가지 판정값을 구분했다

| 판정 | 의미 |
| --- | --- |
| 일치 | 제목에 주장이 있고, 같은 맥락의 본문 근거가 이를 뒷받침함 |
| 차이 | 대응 근거가 있지만 대상·금액·기간·단계 등의 의미가 다름 |
| 근거 없음 | 제목에는 주장이 있지만 대응하는 본문 근거를 확인할 수 없음 |
| 제목 주장 없음 | 제목이 해당 조건을 주장하지 않음 |

‘제목 주장 없음’과 ‘근거 없음’을 구분하는 것이 중요했다. 본문에 금액이 있어도 제목이 금액을 말하지 않았다면, 제목의 금액 주장을 임의로 만들어 비교하지 않았다.

판정 근거는 제목 표현, 본문 근거, 비교 단위, 판단 이유를 중심으로 기록했다. 다른 사람이 같은 사례를 다시 읽고 판정을 논의할 수 있도록 하는 것이 목적이었다.

## 3. 경계 사례를 통해 기준을 구체화했다

### 금액: 숫자와 의미를 함께 봤다

같은 사업의 총사업비를 반올림해 표현한 경우와, 개인 지급액의 ‘최대’ 제한을 생략한 경우는 구분했다. 전자는 표현의 정밀도 차이일 수 있지만, 후자는 실제 받는 금액에 대한 해석을 바꿀 수 있었다.

비교에 앞서 총액인지 가구당 금액인지, 같은 대상과 지급 주기를 말하는지 확인했다. 총사업비에서 적용한 반올림 기준을 모든 개인 수령액에 그대로 확대하지 않았다.

### 기간: 날짜보다 기간의 종류를 먼저 구분했다

신청 기간, 지급 시점, 사용기한은 다르다. ‘한시’, ‘연장’, ‘매월’처럼 날짜 숫자가 없는 표현도 기간이나 주기를 주장할 수 있었다.

같은 사업의 같은 시간 조건을 비교해야 했으며, 본문에 사용기한이 있다는 이유만으로 제목의 신청기한을 뒷받침한다고 보지 않았다.

### 확정성: 미래 일정과 미확정을 구분했다

권고·발의·심의 중인 제도와 결정·시행 단계의 제도를 구분했다. 미래 날짜가 적혀 있어도 이미 결정된 지원일 수 있으므로, 날짜와 정책 단계를 별도로 살폈다.

### 무관한 본문: 기사 전체 문제와 조건별 판정을 구분했다

제목과 전혀 다른 주제의 본문이 붙어 있더라도 모든 조건에 같은 판정을 주지는 않았다. 제목이 금액을 주장했다면 대응 근거의 부재를 살피고, 금액을 주장하지 않았다면 ‘제목 주장 없음’으로 구분했다.

## 4. 설명을 위한 합성 예시

아래 문장과 판정은 포트폴리오 정리 과정에서 작성한 설명용 합성 예시다. 실제 기사 원문, 대회 시험 입력 또는 모델 실행 결과가 아니다. 각 행은 지정한 조건만 설명한다.

| 조건 | 합성 제목 | 합성 본문 | 설명용 판정과 이유 |
| --- | --- | --- | --- |
| 금액 | 해당 가구에 100만원 일괄 지급 | 해당 가구에는 소득에 따라 최대 100만원을 차등 지급한다. | 차이: 정액과 상한·차등 지급의 의미가 다름 |
| 기간 | A 지원금 신청은 12월 31일까지 | A 지원금 신청은 11월 30일 마감하며, 지급된 지원금은 12월 31일까지 사용할 수 있다. | 차이: 사용기한을 신청기한으로 표현함 |
| 확정성 | A 지원금 신설 확정 | 위원회는 A 지원금 신설을 권고했으며 도입 여부는 아직 결정되지 않았다. | 차이: 권고를 확정으로 표현함 |
| 금액 | A 지원금 신청 안내 | A 지원금은 자격을 충족한 가구에 최대 50만원을 지급한다. | 제목 주장 없음: 제목에는 금액 주장이 없음 |
| 금액 | A 지원금 50만원 지급 | A 지원금의 접수 창구는 다음 주 운영을 시작한다. 지급액은 이 글에 제시하지 않았다. | 근거 없음: 제목의 금액을 뒷받침할 정보가 없음 |
| 금액 | A 사업 총예산 약 59억원 | A 사업의 총예산은 58억8,580만원이다. | 일치: 같은 총액을 통상적인 반올림으로 표현함 |

## 5. 두 작업자의 차이를 비교하고 조정했다

기사 ID와 조건을 연결 기준으로 두 작업자의 판정을 대응시켰다. 표기 차이를 정리한 뒤 실제 판정이 다른 항목을 추려, 제목과 본문 근거를 다시 확인하며 기준을 논의했다. 원안과 통합 결과를 구분해 보존했다.

판정 자료를 정리하면서 최초 제출본과 통합 파일에 보존된 작업자 시트 사이에도 수정 차이가 있음을 확인했다. 일치도를 제시할 때는 어느 버전의 두 결과를 비교했는지 함께 기록해야 했다.

작업자 간 일치도는 사람이 같은 기준을 얼마나 공유하는지 살펴볼 자료이며, 모델 정확도나 기준 답안 자체의 객관적 정답률과는 다르다.

## 6. 엔지니어와 평가 단위를 조율했다

조건별 결과가 사람 라벨과 대응돼야 한다고 요청했을 때, 엔지니어는 기사 ID·인용·이유를 JSON으로 출력하고 있어 요구사항을 충족했다고 이해했다. 하지만 기사 전체 판정만으로는 다섯 조건의 기준 답안과 직접 비교하기 어려웠다.

나는 출력 문법뿐 아니라 무엇을 평가할 수 있어야 하는지를 설명했다.

| 조율한 항목 | 필요한 이유 |
| --- | --- |
| 기사 ID와 조건별 연결 | 같은 기사의 같은 조건을 대조하기 위해 |
| 조건별 판정값 | 어떤 종류의 차이를 놓쳤는지 살피기 위해 |
| 제목 인용과 대응 본문 근거·위치 | 비교 대상이 같은 맥락인지 확인하기 위해 |
| 판단 이유 | 판정이 달라진 근거를 다시 검토하기 위해 |
| 범위 판단·조건 판정·처리 경로 구분 | 입력 적합성, 의미 비교, 운영 결정을 섞지 않기 위해 |

사람 기준 답안은 평가에 사용할 목적이라는 점도 전달했다. 다만 실제 개발 과정에서는 팀이 라벨과 일부 불일치 이유를 참고해 지시문·규칙을 수정했으므로, 이후 같은 자료에서 얻은 결과를 독립 평가 성능으로 해석할 수는 없었다.

## 7. 같은 ‘일치’라도 측정하는 것이 달랐다

본선의 현재 구현은 모델이 주장 구절·본문 문장·값을 선택하고 프로그램이 비교하는 방식으로 바뀌었다. 사람의 ‘일치’는 본문이 제목의 의미를 뒷받침한다는 판단인데, 시스템 기록에는 근거 문장의 선택 여부를 나타내는 값도 있었다.

문장을 골랐다는 사실과 그 문장이 주장을 지지한다는 사실은 다르다. 같은 이름의 값을 단순히 비교하기 전에, 의미 판정인지 근거 선택인지 확인해야 했다.

팀은 기존 본문에 새 제목을 붙여 확인 시험도 진행했다. 이것은 기존 사례에서 제목 변화에 대한 반응을 살펴보는 작업으로, 새 기사 본문에 대한 일반화 평가와는 구분했다. 모델 구현과 해당 실험은 모델링 담당자의 작업이었다.

## 8. 인간 검토 조건에 대한 개인 제안

모델이 본문의 ‘최대’ 제한이 제목에서 빠진 차이를 놓친 사례를 공유받았다. 나는 숫자가 같아도 의미가 달라질 수 있어 ‘차이’ 판정이 적절하다는 의견을 냈다.

처음에는 이 경우를 사람 검토로 보내는 방식을 생각했다. 그러나 ‘최대’의 유무만으로 모든 기사를 넘기면 검수량이 지나치게 늘 수 있었다. 이후 다음과 같이 제안을 구체화했다.

1. 제한 조건의 생략을 위험 신호로 본다.
2. 같은 사업·대상·단위의 금액을 비교하는지 확인한다.
3. 자동 통과했을 때 수령액 오해나 신청 기회 상실 등 영향이 클 것으로 예상되는 사례를 우선 사람이 보도록 한다.
4. 모델이 일치로 판단하더라도 별도의 위험 기준에 해당하면 사람이 확인하는 방식을 고려한다.
5. 검수자가 확인할 구절과 위치를 안내해 검토 대상을 구체화한다.

이는 내가 제안한 운영 방향이다. 팀의 현재 구현·채택 정책과 동일한 것으로 보지 않으며, 위험 기준의 정량화와 우선순위 기능의 효과 측정은 완료하지 않았다.

## 9. 결과와 배운 점

조건별 기준 답안을 작성하고, 작업자 간 차이를 조정하며, 엔지니어에게 평가에 필요한 연결 단위를 설명했다. 그 과정에서 수치가 나오기 전에 무엇을 비교하는지 합의해야 한다는 점을 배웠다.

또한 평가 기준과 운영 기준을 구분하게 됐다. 조건에 차이가 있다는 사실을 판단하는 것과, 그 차이에 어떤 검토 자원을 배정할지 결정하는 일은 연결되어 있지만 같은 결정은 아니었다.

현재 자료는 소규모이며 반복 개발에 사용됐다. 이 경험의 결과는 데이터와 평가 기준을 구체화하고 협업에 연결한 것이며, 실제 게시 환경의 정확도 향상이나 검수 시간 절감은 아직 측정하지 않았다.
